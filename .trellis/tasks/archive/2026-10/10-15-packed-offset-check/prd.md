# 加载期打包偏移越限检查

> 中文摘要：在**调试构建**下于加载时复算骨架文件的打包偏移，超出 16 位上限即拒绝加载并给出可定位报错，避免静默产生拉扯的错误几何。位宽加宽（原 Stage 2）已取消。

## Goal

龙骨 runtime 把各部件的偏移（顶点/权重数据在共享缓冲中的下标）打包进 **16 位**元素，读取时靠 `+65536` 回绕补偿。该补偿只能覆盖到 `65535`；超过时真值被截断成一个小正数，回绕不触发，网格读到缓冲里**属于别的部件**的数据，表现为部件大幅拉扯。

本任务在加载阶段检出这类数据并明确失败，使其可诊断而非静默出坏图。

## Background

- 失败机理：`JSONDataParser::_parseMesh` 把 `_floatArray.size()` 快照写进 `int16_t` 缓冲。`real > 65535` 时存成 `real & 0xFFFF` 的小正数（`85878 → 20342`），回绕条件不成立，直接读到别人的数据。
- 截断不可逆：`20342` 本身是合法偏移，故**无法**从缓冲内容反推真值，判据只能来自源数据。
- 受影响的两类偏移：`floatArray` 上的 `MeshFloatOffset` / `WeightFloatOffset`，以及 `intArray` 上的颜色块偏移（`colorOffset`）。
- 偏移按**解析顺序累加**，与单个部件大小关系不大：约 4000 网格顶点或约 3400 蒙皮顶点即越过 32K 的读错线。
- `.dbbin` 不经过 JSON 打包器，其 16 位偏移由官方导出器写死，不在本检查范围。

## Requirements

- **R1**：在加载时按骨架文件复算偏移，超出 `65535` 即判定加载失败。
- **R2**：报错须含资源路径、缓冲名、真实峰值、上限与触发峰值的部件名。
- **R3**：判据用**峰值偏移**而非缓冲总量 —— 单个大网格的偏移可能仍是 0，那种情况窄模式下不会读错，误报会拒绝合法资源。
- **R4**：复算顺序必须与解析器一致（每个 armature 内先 skin 再 animation），否则峰值不准。
- **R5**：检查只在**调试构建**生效；发布构建不执行。
- **R6**：检查不得修改 vendored runtime（`thirdparty/dragonBones/`），实现在 `src/`。
- **R7**：非 JSON 输入（`.dbbin`）不报错，交由既有解析路径处理。

## Acceptance Criteria

- [x] 越限资源被拒绝，报错含缓冲名、峰值与部件名，且与独立复算逐值吻合。
- [x] 6 套既有资源零误报，几何正常。
- [x] 调试构建检出、发布构建不检出（符号与文案均不在 release 库中）。
- [x] 单测覆盖：合法/越限/边界（等于上限合法）/大网格不误报/颜色块独立检出/非 JSON 输入。
- [x] `thirdparty/dragonBones/` 无改动。

- `.dbbin` 输入的越限检测。
